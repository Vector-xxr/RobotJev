# 复合策略抓取

## 抓取本质上需要什么

把物体放到两指中间，然后合爪。要做到这一点，只需要知道两件事：

1. **物体离两指中间还差多少**
2. **臂怎么动，才能缩小这个差**

其他所有东西，都是为了得到这两个量。

## 两件事分别从哪来

**1. 还差多少 = 物体中心 − 夹持中心，都在腕部相机坐标系里**

- 物体中心：由腕部 RGB-D 相机现测。
- 夹持中心：相机装在夹爪上，这个点是固定的，从示范里测一次得到 [15, 32, 88] mm。

**2. 怎么动 = 相机移动 ↔ 臂移动的换算 J**

- 每次在现场点动三个轴，各 ±1cm，看画面里静止的东西怎么移动，就测出来了。

## 谁来做决定

| 决定 | 谁 |
|---|---|
| 往哪个方向走 | PlayJev：把「差多少」画成一帧 Snake，问它上下左右 |
| 走多远、何时往前推、何时到位、何时合爪、成没成功 | 规则，阈值都来自测量值或夹爪尺寸 |

## 流程

### 0. 指令 → 找什么

`"pick up the blue cylinder"` → 去掉动词冠词 → `blue cylinder`
→ 查询词：原短语 / 颜色 + object / 中心名词 = `blue cylinder`、`blue object`、`cylinder`。

### 1. 顶部 Gemini 335 看一眼定位（默认，`--locate top335`，代码在 `top335.py`）

335 有深度，外参标过（`calibrate_top335`，留一误差 ~2mm），所以看一眼就知道物体在基座系哪里，不用闭环。

**不设工作空间之类的专用限制，335 看得见的都算。** 选哪个、能不能抓只看物理条件：

1. **候选**：YOLO-World 找框，CLIP 名次 <= 3，按 CLIP 余量从大到小逐个看。没有「框面积不超过画面 1/4」这类规则。
2. **能不能抓**，两条都满足才选：
   - 夹得下：抓取高度以上的物体点，沿夹爪开合方向的宽度 ≤ 满开 98mm − 预留 12mm。开合方向 = 腕部相机 x，由 J 给出。
   - 够得着：抓取点、预抓取点、平移点的逆解都要解得出。
3. **抓不了的不悄悄丢掉**：每个都打印「看到了但抓不了：…… —— 原因」（逆解不出 / 比夹爪宽）。
4. **帧间连续**：第一帧定下目标后，后面几帧只认水平位置离它 5cm 以内的。抬起后判「跟没跟着走」也按这个位置认。
5. **接近路径**：到不了时按顺序退让，不硬性规定：
   - **预抓取点**：沿腕部视线后退 10cm，到不了就试 8cm、6cm。
   - **平移高度**：首选 0.40m（标定时整张网格在这个高度走过，没碰到任何东西）。到不了就往下降，但不低于「335 看到的走廊里最高的东西 + 8cm」。走廊指夹爪连同机身扫过的范围。走廊里看不见东西时不降。
6. **环境边界**：只在这个进程里，换掉 AR5Config 的工作空间盒（那是遥操用的）：
   - 水平和上方不限，由逆解决定。
   - 法兰下限 = 335 量的支撑面 + 12mm。指尖在夹持中心下方 11.8mm（夹爪标定），所以这时指尖正好贴着支撑面、不插进去。
   - 原来的 z 下界 0.08 和关节地板 0.10 是按因时手推的。换成 TG9801 后，法兰到 0.08 时手指已插进桌面 9cm，既不限制也不保护。

9/29 离线扫描，固定朝向下桌面 5cm 网格（抓取法兰 z=0.19）：
- 抓取点够得着的有 145 格，旧流程能走通 99 格。
- 降低平移高度多通 13 格，缩短后退多通 3 格，两者都要多通 4 格。
- 剩下 26 格：11 格是预抓取点够得着、但平移高度怎么降都不行；15 格是预抓取点怎么缩短后退都够不着。
- 真正卡住的是**固定朝向**：y > 0.1 的一大半桌面，固定朝向下连抓取点都逆解不出。要放开，得让夹爪绕竖直轴转。转了之后外参里「法兰 → 夹持中心」这段偏移会跟着转，所以要先在几个朝向下标出这段偏移（要动臂，未做）。

### 1'. 旧：俯视 UGREEN 闭环把夹爪带到物体上方（`--locate top`，相机已换下，别用）

不用示范，不用标定，所有量都是现场测的。俯视相机能看到、臂能够到的地方都可以抓。

1. **物体像素**：在俯视图里测一次。
   - YOLO-World 只用上面三个查询词找框。
   - CLIP 把每个框和几句话比：一边是目标描述，另一边是背景描述加 COCO 80 类名。目标描述排进前 3 才算。
   - SAM 分割后取掩码质心。
2. **起点**：臂移到固定高度、固定朝向的起点，法兰在 [0.333, −0.257, 0.33]。之后只在这个水平面里移动。
3. **夹爪像素**：夹爪开合一次，俯视画面里只有手指在动，变化像素的质心就是夹爪位置。碰到画面边缘的不算。
4. **像素 ↔ 臂移动**：臂沿 x、y 各点动 ±2cm，看夹爪像素怎么移动，得到一个 2×2 矩阵。正反两次结果不一致就重测。
   - 这个矩阵只取决于俯视相机的摆放、起点和朝向，所以测一次后存进 `calibration/top_A.json`，之后直接用。
   - 每走一步都拿实测的夹爪像素和矩阵的预测比。对不上时先重认一次夹爪，还对不上就删掉缓存，下次重测。
5. **闭环**：计算画面里夹爪到物体的像素差，由 PlayJev 选上下左右，沿选中的方向一次走完这个方向的差（每步最多 15cm），走完重测夹爪像素。差 < 10px 就交接。一般 3 步。

俯视相机没有深度。画面里重合时，夹爪其实在物体前方、靠俯视相机那一侧，而腕部相机正朝那个方向看，物体在它身后。所以下一步要往回退。

### 2. 腕部相机：测 J，把物体找进画面

1. **测 J**：三个轴各点动 ±1cm，用整幅静态场景的光流加深度测相机位移，比手指近的点不算。结果再投影成正交矩阵。
   - 固定朝向下 J 是常量，每次测成功都存进 `calibration/wrist_J.json`。
   - 画面没纹理、测不出来时（比如只看到白墙），就用存下的那个。
2. **算出往回退多少**：一步移过去，所有量都来自腕部深度和 J。
   - **桌面**：在腕部深度里，沿竖直方向把点按高度分层，取水平方向离夹爪最近的那一层大面积水平面，再用 RANSAC 拟合。竖直方向由 J 给出。
   - 不能取「内点最多的平面」：画面里地面和墙占了大半。
   - 也不能取「最高的一层」：远处可能有别的水平面比泡沫板高。
   - 把夹持中心竖直投到桌面上，得到点 O；物体大致就在 O。
   - 光轴和桌面的交点，就是画面中心看到的点 p。
   - 臂水平移动 Jᵀ(p − O)，让 O 落到画面中心。
3. **兜底搜索**：还看不到才小范围搜：往回退 5 步，再左右试。看到后先粗对中到画面中间。

旧的粗定位方式还在：`--locate demo` 用示范单应矩阵，并抄示范的出发姿态。

### 3. 腕部相机：测「还差多少」

每一步都重测，五帧取中位：

```
YOLO-World 找框 → CLIP 确认 → MobileSAM 分割 → 去畸变 → 对上深度 → 物体点云
物体外面一圈的深度点 → RANSAC 拟合桌面
物体高度 = 物体点到桌面的最大距离（97 分位）
物体中心 = 物体点投影到桌面的中位 + 沿法向抬高半个高度
物体尺寸 = 点云 xy 的 2~98 分位
抓取点 = 物体顶部那一截的中心（见下），伺服对准的是它，不是物体中心
```

拟合不出桌面时，退回用「可见面 + 最窄维一半」估中心。

**抓取点：抓物体最上面那一截**

- **矮物体**（低于 2 倍手指长度，约 56mm）：抓半高，乒乓球、套筒、胶带都是这样。
- **高物体**：从顶部往下，每 3mm 一层量宽度（沿夹爪开合方向）。宽度和上面各层的中位数差出 ±3mm，或者这一层深度点太少，就停下，指尖落在那一层。最深不超过手指长度。
  - 宽度一变，就说明换到了物体的另一部分。水瓶就是这样只夹住瓶盖，不碰下面透明的瓶颈和凸环。
  - 透明部分深度点稀疏，量出来反而会变窄，所以变窄也要停，不能只看变宽。
- 这个高度在交接时（离物体 20~30cm）定下来，之后**冻结**。贴近以后只看得到顶面、看不到侧面，逐层宽度就量不准了。
- 抓取点的水平位置和抓取处宽度，只用这一截的点来算。

### 4. 伺服：一步一步缩小差

`e = 抓取点 − 夹持中心`

- **横向（画面 x/y）**：把 e 画成 Snake，由 PlayJev 选上下左右。每步最多走 12mm，离得近时 5mm。
- **往前（光轴 z）**：只在物体已经落在两指之间时才往前推。否则一根手指会先戳到物体上，或插进物体的孔里。
  - 开合方向：|ex| < (夹爪满开 98mm − 抓取处宽) / 2
  - 另一方向：|ey| < 抓取处尺寸 / 2
  - 往后退不受这个限制。
- **到位**：|e| < 6mm。
- **被顶住就停**：每步都小于缰绳 15mm，正常情况下缰绳不会触发；一旦触发，就说明臂被东西挡住了。
- 最多 45 步。

### 5. 合爪、抬起、判成败

1. **合爪**：力度只由 CLIP 决定（`grip_force.py`）。CLIP 看腕部截图，结合物体名提示词，判成易碎、软、硬三类之一，每一类对应一档力度和一个合爪速度：

   | 类别 | 力度档位 | 合爪速度 |
   |---|---|---|
   | 易碎 | 5 | 200 |
   | 软 | 15 | 500 |
   | 硬 | 50 | 1000 |

   先快速合到比物体宽 12mm，再用这一档合一次，然后等 2 秒。9/29 去掉了滑落检测（原来是从 1 档起、试抬 15mm、滑了就加一档）。
2. **抬起**：往上 60mm。
3. **判成败**，两条都满足才算成功：
   - 夹爪读数 ≈ 1 − 抓取处宽 / 98mm，差 < 0.2。
   - 物体可见表面在相机系里移动 < 30mm，也就是抬起距离的一半。没抓住的话，物体会留在桌上，相机却升了 60mm。
   - 抬起后看不到物体时（比如瓶盖贴着镜头），改看两指之间的深度点：抬起后还剩合爪前的 30% 以上，就算还在。

**夹爪几何自标定**：加上 `--calib-gripper`，开头会在 0 位让腕部相机看自己的手指，结果写进 `calibration/gripper.json`。

- 手指根部和指尖的位置：由此得出夹持中心往上到手指根部是 28mm，也就是物体顶部最多能伸进两指之间多深。
- 满开宽度：拟合残差太大时不采用，保留手册的 98mm。手指是黑的，只有边缘有深度，这一项测不准。

## 命令

一共要开两个终端，用两个 conda 环境：

| 做什么 | 环境 | 目录 |
|---|---|---|
| PlayJev 服务 | `playjev` | `~/yuhang_workspace/算法/Jev/RoboJev/PlayJev` |
| 抓取、放回、上电 | `laya` | 抓取、放回在 `~/yuhang_workspace/算法/Jev/RoboJev`；上电在 `~/yuhang_workspace/数据_硬件/SO101` |

每条命令前都要加 `PYTHONPATH=`，把 PYTHONPATH 清空。原因是 ROS 往 PYTHONPATH 里塞了自己的包，会让导入报错。

**终端 1：PlayJev 服务**

启动后一直开着，占用 GPU，一次请求约 23ms。

```bash
conda activate playjev
cd ~/yuhang_workspace/算法/Jev/RoboJev/PlayJev
PYTHONPATH= python -m playjev.serve --ckpt weights/PlayJev-0.8B --port 18732
```

**终端 2：抓取**

```bash
conda activate laya

# 臂没上电，或者刚松开急停时，先上电：
cd ~/yuhang_workspace/数据_硬件/SO101
PYTHONPATH= python -m atom_robot.ar5.power_on --enable --yes

# 抓取、放回：
cd ~/yuhang_workspace/算法/Jev/RoboJev
PYTHONPATH= python -m robojev.run_composite --instruction "pick up the blue cylinder" --stage grasp
PYTHONPATH= python -m robojev.place_and_home --down 0.06    # 抬多少降多少，放回，张爪，回 0 位
PYTHONPATH= python -m robojev.place_and_home --no-place     # 手里没东西，直接回 0 位
```

两个可选参数：

- `--record 目录`：每 0.25 秒存一帧「俯视 | 腕部」拼图，文件名带阶段和步号，出问题时逐帧对照日志。
- `--calib-gripper`：先标定夹爪几何，见上面第 5 步。

```bash
PYTHONPATH= python -m robojev.run_composite --instruction "pick up the water bottle" --stage grasp --record /tmp/rec
```

换物体只需要换指令，指令用英文。

**点选抓取（不给指令，鼠标点）**：

```bash
PYTHONPATH= python -m robojev.click_grasp                 # 弹出 335 的一帧，点物体，Enter 抓
PYTHONPATH= python -m robojev.click_grasp --dry           # 只点选、看判定，不连臂
```

窗口操作：

| 操作 | 作用 |
|---|---|
| 左键 | 点物体 |
| 按住左键拖 | 框选 |
| Shift+左键 | 再加一个点 |
| 右键 | 排除点 |
| Tab、空格或滚轮 | 换分割粒度 |
| Enter | 抓当前选中的（只接受判为能抓的） |
| Esc | 退出 |

- **判定**：选中的物体会画出轮廓和框，并显示名字、高度、宽度和能不能抓。判能不能抓用的是同一个 `top335.feasibility`，另外要求物体高出支撑面 12mm 以上，避免点到坑或平面。
- **连臂时机**：确认后才连臂。臂回 0 位后，用同样的提示在新画面上重新分割，和点选时的掩码重合度低于 0.5 就不抓。
- **腕部接手**：点选的物体没有可靠的名字，所以按 335 测的抓取点投影到腕部画面：`G − J·(f_grasp − f_now)`。在那里用点提示分割，和 335 的预测相差超过 30mm 就改走 335 直线接近。
- **伺服**：每帧在上一次掩码的内点给点提示，臂动后按 `J·b` 预测物体的新位置。
- **实测**（9/29 15:16）：乒乓球一次成功。腕部分割结果和 335 预测相差 9mm，伺服 8 步，1 档力就夹住了，约 31s。

运行前还要检查一件事：相机和串口不能被别的程序占着，比如 collect。用这条命令查：

```bash
fuser /dev/video* /dev/ttyUSB* /dev/ttyACM*
```

有输出就说明被占了，先停掉那个程序。

## 为什么这样设计：每条都是踩坑踩出来的

| 现象 | 原因 | 改法 |
|---|---|---|
| 充电器被认成遥控器 | YOLO-World 每个框只留分最高的类别 | 只查指令里的说法 |
| 平放的胶带被估到桌面以下 | 用「宽的一半」当厚度 | 拟合桌面，实测高度 |
| 离物体只剩 2~3cm 时目标丢了 | 物体靠近后框顶到画面边缘，被当成出界 | 伺服阶段不设画面边缘限制 |
| 手指插进套筒孔里 | 横向还差 48mm 就往前推 | 物体进了两指之间才往前推 |
| 离物体很近时来回振荡 30 步 | 手指、飞点、阴影混进桌面采样，高度测成 30mm（实际 47mm） | 桌面拟合改成 RANSAC |
| 胶带真抓住了却被判失败 | 抓起后中心就算不准了 | 判成败改看可见表面的位移 |
| 粗定位只在示范覆盖区域有效 | 示范单应矩阵 + 抄示范姿态 | 改成俯视图像空间闭环 |
| 俯视对准了，腕部却看不到物体 | 俯视有视差，腕部相机朝前看 | 沿视线方向往回退，方向由 J 给出 |
| 抓高物体时掌心先压到瓶盖 | 沿斜光轴推向物体半高中心，瓶盖正挡在路上 | 抓顶部那一截 |
| 瓶子被挤走、合空 | 手指伸进 28mm，指尖落在瓶盖下的斜面上 | 逐层量宽度，宽度一变就停 |
| 抓起后瓶子滑脱 | 透明瓶颈量成变窄，规则只看变宽，一路伸到瓶颈 | 变窄也停 |
| 真抓住了却判失败 | 瓶盖贴着镜头认不出 | 看不到时改看两指之间的深度点 |
| 板子远端测不出 J | 腕部只看到白墙，没纹理 | 用上次测成功的 J |
| 臂动着动着锁死 | 0.25 秒收不到新指令就锁存 | 加看门狗线程 |

## 必须知道的

- 腕部相机的 OBSENSOR 接口和 collect 用的 V4L2 接口会互相干扰，两者不能同时开。换接口前要复位 USB，再等 8 秒。
- 急停按下后，要先手动松开急停，再运行 `python -m atom_robot.ar5.power_on --enable --yes`。急停也会让夹爪断掉反馈。
- 远处第一次测的高度可能离谱，比如套筒测出过 156mm，靠近后会自己纠正。
- 成功记录（9/28 当前代码，俯视粗对准 + 抓顶部）：
  - 蓝色套筒：换过多个位置都成功。
  - 乒乓球：成功。
  - 水瓶：只夹瓶盖，最终规则下连续 3 次成功（前两次抓取高度 160mm；换位置后那次交接时离得太近、从正上方看，只伸进 8mm，偏浅）。之前 3 次失败，原因见上表。
  - 黄胶带：只在旧代码下成功过 1 次。
  - 白色充电器：一直没成功。
- 还没解决：固定朝向下 y > 0.1 的一大半桌面、离底座太近的位置都够不着（j4 顶到 142°），要让夹爪能绕竖直轴转，见第 1 节末尾。平移高度已改成可按 335 走廊下降。
