# PlayJev 微调：DAgger 方案

2026-09-28。前提是 PlayJev（0.8B，OmniJev/PlayJev-0.8B）已在 AR5 + TG9801 上用「渲染成 Snake」
的方式真机抓起过蓝色套筒，见 `robojev/run_playjev.py`。

## 1. 为什么要微调、微调什么

现在的分工（全部实测过）：

| 判断 | 谁做 | 表现 |
|---|---|---|
| 平面方向（上下左右） | PlayJev，输入是渲染的 Snake 画面 | 离线 100%，镜像检验 100% |
| 走多远、下探多深、何时合爪、成没成功 | 规则 | 模型做不了：数值输入它读不懂 |
| 目标在哪 | 颜色分割 / YOLO-World + 单应性 | 单应性留一法误差中位 5.9 mm |

**方向这一项不需要微调。** 值得微调的只有两个目标，它们对 DAgger 的需求完全不同：

- **目标 A：直接看真实照片**，省掉检测 + 单应性这一层，换物体不用重做感知。
  PlayJev 零样本看真实俯视图是不行的：左右镜像后概率不交换，遮掉目标反而更自信
  （`robojev/probe_playjev.py`）。**这个目标需要真实画面，也就需要真机数据。**
- **目标 B：连「合爪 / 停止」也让它管**。在 Snake 画面里加一个 `grasp` 选项，原游戏里没有这个动作，
  所以必须训。**画面是合成的，DAgger 可以全部离线跑，一次都不用动臂。**

## 2. 真机 DAgger 贵在哪

常规 DAgger 贵在「学生走到的每个新状态都要专家标注」。**我们的专家标注是免费的**：
几何策略（或者渲染 + PlayJev 那套）对任何状态都能自动给出正确动作。真正的成本是三样：

1. **臂的运行时间**：一次尝试（对准 5~10 步、每步走完再停稳、下探、合爪、放回、回 0 位）约 20~40 s
2. **复位**：抓完要把物体放回去，最好是随机放到新位置
3. **有人看着**：第一次让学生策略上真臂，没法完全不看

粗估：一小时 100~150 次。PlayJev 原配方是克隆一轮 + 3 轮 DAgger，每轮几百次，
**一轮要跑几个小时。只有全自动、能自己复位，才能过夜无人值守地跑。**

## 3. 分阶段计划（投入从小到大）

### 阶段 0：先把自动化做完（前置条件）
没有它，后面每一轮都要人守着。需要：
- 开机自检：GPU、PlayJev 服务、相机按厂商 ID 找口、串口占用、俯视相机有没有被碰歪
- 成功判定：合爪后夹爪读数（≈0.99 = 空抓，0.3~0.9 = 夹住了，<0.3 = 手指没合上）+ 俯视画面里目标离开原位
- **自动复位**：抓起后放到示范覆盖范围内的随机新位置，再回 0 位
- 每一步都记录：画面（俯视 + 腕部）、指尖位置、专家动作、学生动作、成功标记

### 阶段 1：离线行为克隆，不用臂
- **数据**：`~/atom_episodes` 里 107 条去重后的示范，每帧都有俯视 / 腕部视频和 `ee_pose`。
  标签 = 「接下来约 0.3 s 指尖往哪走」离散成 上/下/左/右/不动，合爪那一刻标 `grasp`。
- ⚠️ **任务标签不可信**：`grasp1` 里很多条标的是 "pick up the pingpong ball"，实际抓的是水瓶。
  要按画面判断抓的是什么（例如「合爪后目标离开原位」），别信 `task` 字段。
- 按 `playjev.collect` 的输出格式写一个转换器，接 `playjev.train_sft`。

### 阶段 2：用自动化跑出来的数据
阶段 0 跑起来之后，每一次尝试的每一步都是带标签的样本（专家动作是现算的），不需要额外标注。

### 阶段 3：小规模真机 DAgger，1~2 轮
- **每轮 50~100 次，不要几百次**。集中在学生出错多的区域，比如覆盖范围边缘、目标贴着别的物体。
- **按概率执行专家动作（β 混合）**：每一步以概率 β 执行专家动作、否则执行学生动作，β 逐轮降低
  （例如 0.5 → 0.2）。失败的回合少了，复位次数也就少，状态又不会离学生的分布太远。
- 每一步都同时记下学生动作和专家动作，**标签永远用专家的**。

### 阶段 4（不建议现在做）：数字孪生仿真
投入最大，真实图像还有从仿真到真机的差距。等上面几步的上限到了再考虑。

## 4. 训练细节

- **软标签**：目标在斜对角时，上和左两个方向都对。标签要把概率平分给所有正确方向；
  只标一个，就是在逼模型学一个随意的偏好。
- **显存**：README 写 batch 64 要 17 GB，这张 RTX 5070 Ti 只有 16 GB。
  batch 降到 16~32，或者用 LoRA（`playjev` 环境里已经装了 `peft`）。训练时要先停掉 PlayJev 服务（占 3.6 GB）。
- **防遗忘**：照 PlayJev 原配方，掺 20% 通用图像问答 + 20% 纯文本数据。
- **选项顺序打乱**：原训练里每个样本的选项顺序都是随机的，位置不携带信息，这一点要保持。

## 5. 验收顺序（前一关不过不进下一关）

1. **离线检验**（`robojev/probe_playjev.py`）：左右镜像后概率要跟着交换；遮掉目标后分布要明显变化；
   和空白图的 L1 距离要明显大于 0。零样本时这三项全挂。
2. **离线方向准确率**：留一部分示范做测试集，和几何专家比，要明显高于随机基线。
3. **mock 臂闭环**：用 `--sim` 跑整条状态机。
4. **真机闭环**：先 `--align-only`，确认对准再下探；统计 N 次的成功率，而不是只看一次成没成。

## 6. 已知的坑（都是今天踩过的）

- RT 发送线程：**臂在动时 0.25 s 收不到新目标就锁存**，之后全被拒，统计里显示成「不可达」，很像 IK 问题。
  每步之后必须持续重发同一目标直到停稳（`run_playjev.settle`）。模型推理再慢都不能让流断。
- 目标检测要在**连臂之前**做，连上之后不能先干 2 s 别的。
- 夹爪闭合要 1.6 s，合爪后等 ≥2 s 再抬。
- 本机请求别走代理：服务挂了时代理会回 502，把真实原因遮住。
- 机器重启后 PlayJev 服务不会自己起来；内核升级后 GPU 驱动可能掉。GPU 挂了可以临时用 `OmniJev/serve_cpu.py`（253 ms/次）。
